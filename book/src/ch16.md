**状态：已实现并验证（Python M4–M10 组合入口）。** 本章把前面独立切片接回同一条离线链路；它不声称已经集成 HUSH Runtime、Forge Studio 或真实 Provider。

## 16.1 一条可审计的方向

组合方向是：

Context → Model action → Tool schema → EffectIntent → Policy → Idempotency → Effect → Validation → Evidence → RunOutcome

Runner 在每次模型请求前检查取消和预算；工具输入在 policy/ledger 前检查；effect 在 policy allow 后 reserve；工具失败记录为结构化结果；final text 经过 Validator 后才是 Completed。EventLog 保存事实，Trace/Summary/ReviewBundle 只读投影或摘要绑定。

~~~python
provider = FakeProvider([ModelResponse("done")])
result = Runner(provider).run("answer")
assert result.reason == StopReason.COMPLETED
~~~

## 16.2 成功和失败路径

成功路径是 fake provider 返回文本，默认 nonempty validator 通过并记录 terminal event。重要失败路径包括输入 schema 错误（不执行 handler）、effect 缺少批准而 ESCALATE、幂等结果未知而 STOP、validator 失败、重复 call_id、跨 run evidence 和 stale ChangeSet。

HarnessProfile 和 compose_profile 只检查扩展身份与工具集合；它们不是权限模型。ExtensionGateway 要求 policy、validation、evidence 三道门，扩展不能直接宣布 Run Completed。
