# 阅读指南：如何使用本书

本书面向两类读者：已经了解 Agent 和基本计算机概念、但几乎没有独立完成大型项目经验的学生；以及希望跨界学习 Agent 的工作者。

## 你需要什么基础

正文不承担完整的 Python、终端或 Git 入门，但你最好能够：

- 读懂变量、函数、条件和循环；
- 在终端中进入目录、运行命令并查看错误；
- 理解 JSON 对象、数组和字符串；
- 知道 HTTP 请求包含 URL、Header、Body 和状态码；
- 能创建文件、修改文本并查看差异。

本书的 Python 示例要求 **Python 3.10 或更高版本**。M1 协议类型使用了 `X | Y` 联合类型标注；在 Python 3.9 中，这段标注会在导入时失败，而不是只少一个类型检查功能。运行示例前先确认：

```bash
python3.11 --version
```

这里的 `python3.11` 只是本仓库当前验证使用的解释器名称；Python 3.10、3.12 或更高版本也可以。若你的系统将 3.10+ 版本命名为 `python3`，可以直接替换命令中的解释器名称。

如果这些内容还不熟悉，先完成一条短预备路线：Python 基础语法 → 终端文件操作 → Git 基础 → JSON 与 HTTP → 再回到第 2 章。预备学习的目标是能运行本书示例，不是先学完整的软件工程课程。

## 三条阅读路线

```text
概念路线：ch0 → ch1 → 各章小结
实践路线：阅读指南 → ch2 → ch3 → ch4 → 实现索引
系统路线：ch5 → ch16，结合每章的设计状态和验证场景
```

正文优先使用 Python 风格伪代码和经过测试的 Python 片段，让读者先理解控制流和失败路径；已经验证的其他语言实现则通过实现索引引用。

## 为什么正文 Python-first，同时保留 Rust 对照

正文选择 Python，不是因为 Agent Harness 只能用 Python 实现，而是因为读者可以用较少的语法负担先看清请求、协议、工具调用、循环和失败路径。教学主线首先要暴露控制流：模型收到了什么、提出了什么、Runtime 执行了什么，以及验证为何通过或失败。

Rust 对照实现承担另一项任务。类型、错误、状态与资源边界在 Rust 中需要更显式地表达，这使它适合检验同一设计在更严格约束下是否仍然成立。但语言本身不会自动带来安全或可靠；工具权限、路径边界、验证和停止策略仍然必须由 Harness 设计。

因此，本书根据读者门槛、任务风险、生态支持、跨平台要求和验证成本选择实现语言，而不把某一种语言写成普遍答案。当前实现索引只列出已经存在并经过验证的 Python、Rust 版本；TypeScript 会在实现、离线测试和类型检查都具备之后再加入。

从 CH06 到 CH16，累计 Python 主线位于 tutorial/python/agent_harness，章节 demo 和测试位于 examples/python/m4–m10。它们是已实现并验证的内存教学切片；Rust P0 仍是独立的参考组合，不能互相替代。

## 章节状态如何阅读

- **已实现并验证**：可以直接运行对应命令，并以源码和测试为准。
- **P0 参考实现**：用于展示确定性组合，不代表真实 Provider、持久化或生产安全能力。
- **设计骨架/尚未实现**：本章先冻结问题、抽象和测试目标，不能把示例当成已完成代码。

章节编号是阅读顺序，M0–M10 是教学实现增量，P0 是一条确定性垂直切片。它们可能同时谈论同一组件，但表示的完成状态不同。

## 本书的连续案例

第 2–4 章围绕同一个问题推进：

```text
请读取工作区 hello.txt 的第一行并告诉我内容；
如果无法访问文件，不要猜测。
```

第 2 章展示模型只能生成文本；第 3 章把 `read` 表达成统一协议中的候选动作；第 4 章才让受控 Runtime 执行读取并返回 `hello workspace`。后续章节会继续追问：循环如何继续、上下文如何裁剪、失败如何恢复，以及结果如何验证。

## 每章末尾的工程分析层

从第 2 章开始，每章正文后都有一层工程分析。它不是把“本章学到了什么”换一种说法，而是回头查看 Harness 的现场：本章前后哪条路径发生了变化，这个变化让系统具体获得了什么，又把哪些风险带了进来。

分析层的标题会随章节变化。模型调用章节会重点看 Provider 边界和失败证据；Tool Runtime 章节会重点看执行权限和副作用；状态与恢复章节会重点看事实源、重复执行和可恢复性。阅读时可以连续追踪四个问题：

- 能力是否真的新增，还是只新增了一个名字；
- 当前状态来自已运行的代码、P0 参考实现，还是尚未实现的设计合同；
- 这次抽象解决了哪个具体问题，代价和新的失败路径是什么；
- 当前系统暴露出的下一个问题，为什么值得成为下一章。
