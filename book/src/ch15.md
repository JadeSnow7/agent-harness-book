# 第 15 章：MCP、Skills、Hooks 与 Plugin

**状态：设计骨架/尚未实现。** 本章只建立扩展边界和验证要求；当前仓库没有 MCP、插件 ABI 或插件市场实现。

前面已经有 Tool、Context、Policy、Event 和 Run。遇到 MCP、Skill、Hook、Plugin 时，不要先背生态术语，先问它们接入了哪个已有边界。不同产品对这些词的定义可能不同，下面只给出本书的工作定义。

## 15.1 学习目标

完成本章后，读者应能把外部能力映射到 Tool、Context、Policy 或生命周期事件，并为远程内容、插件 manifest 和 hook 失败设计 capability 与脱敏检查。

## 15.2 四种接入方式

- **MCP**：把外部 Tool、Resource 或 Capability 接入 Harness；远端 server 仍是不可信边界。
- **Skill**：Instructions + Context + Capability 的可复用任务包，不是一个拥有无限权限的 prompt 文件。
- **Hook**：生命周期扩展，例如在 `RunStarted`、`ToolStarted` 或 `ValidationCompleted` 时观察、拒绝或补充信息。
- **Plugin**：更宽的 Harness 扩展机制，可能增加工具、存储、模型适配器或 UI；因此必须声明能力。

```text
External server → Tool/Resource adapter → Policy → Runtime
Skill           → Context + Instructions + capabilities
Hook            → lifecycle event boundary
Plugin          → versioned extension + capability manifest
```

术语不是标准化同义词。某产品称为 Skill 的东西，另一个产品可能称为 Prompt Template 或 Plugin。

## 15.3 安全边界

远程工具的描述、返回内容和资源都可能包含 prompt injection 或工具投毒。Harness 不能因为描述来自“协议”就跳过 schema、Policy、超时、来源和输出限制。插件 manifest 至少应声明版本、入口、文件/进程/网络 capability、来源和撤销方式。

```text
manifest → capability diff → user/policy decision → sandboxed lifecycle
```

Hook 也不能绕过 Policy：一个“工具执行前 hook”若能直接运行另一个命令，它就是新的高风险 capability。扩展错误应进入事件和 Outcome，不应静默改写任务状态。

## 15.4 验证场景

离线测试可用假的 MCP server 和假的 Plugin：检查工具 schema 映射、超时、能力 diff、秘密脱敏、版本不兼容以及 hook 失败路径。不要把真实远程 server 或凭据放入默认测试。当前 P0 明确排除 MCP、GUI、分布式执行和插件市场，所以本章只建立接口方向。

验证场景：使用假的 MCP server 和假的 Plugin 检查 schema 映射、超时、能力差异、秘密脱敏、版本不兼容以及 hook 失败。默认测试不连接真实远程 server，也不使用凭据。

## 15.5 本章将得到什么

完成 M10 扩展边界后，系统将拥有版本化 capability manifest 和生命周期插槽的设计方向；生产级插件 sandbox、供应链验证和 durable 外部连接仍未实现。

## 15.6 扩展点越开放，能力声明越不能省略

本章的收益不是接入了 MCP 或插件，而是为扩展建立了共同问题：它究竟增加 Tool、Context、Policy、Event 还是 Runtime 能力，生命周期在哪里，失败怎样回到事件和 Outcome。Capability manifest、schema 映射和脱敏要求让外部能力至少有机会在执行前被审查，而不是因为名称叫 Skill 就获得无限权限。

代价是供应链和远程边界进入 Harness。工具描述可能携带 prompt injection，远程结果可能投毒，Hook 可能偷偷启动另一个高风险动作，插件版本和撤销策略也会影响可复现性。即使 schema 正确，网络超时、版本不兼容和秘密泄露仍然是运行风险。扩展 API 过早冻结，还会把尚未理解的产品差异硬塞进公共核心。

| 能力 | 当前状态 |
| --- | --- |
| M2 Tool/Context/Policy/Event 的现有边界 | 已实现或有 P0 参考 |
| MCP、Skills、Hooks、Plugin manifest 与 lifecycle contract | 设计骨架/尚未实现 |
| 真实远程连接、插件 sandbox、供应链签名和撤销 | 尚未实现 |

当前成熟度是 **Experimental**：本章提供的是扩展分类和验证合同，不是生态兼容性承诺。有意留下的技术债是先用 fake server 和 fake plugin 验证能力差异与错误路径，不连接真实服务。下一章必须展示组合，而不是继续新增术语：只有把通用核心和领域 adapter 分开，读者才能判断一个完整 Harness 到底完成了什么。
